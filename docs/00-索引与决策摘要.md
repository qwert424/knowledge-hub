## 2. 一句话方案

**四端 + 一个内部引擎**：

- **前台（用户端）**：类千问/文心的对话工作台，SSE 流式、引用溯源、知识库选择、反馈。
- **后台（管理端）**：RAG/Agent 统一控制台，8 大业务模块 + 4 个平台治理模块，全部通过 Java 后端调接口。
- **后端（Java）**：唯一控制面。负责身份、权限、知识库元数据、数据源、索引任务编排、策略配置、会话、审计、配额，并把 LiteLLM/Nacos/Langfuse/OpenSandbox/MinIO 封装成稳定的内部 API。
- **Agent（Python）**：LangGraph Server（对话/检索 Agent）+ RAG Engine（解析、切片、向量化、图谱构建、检索执行，两个进程同一代码库）。
- **内部引擎（RAG Engine）**：不是第五个产品部分，是 Agent 部分里的一个部署单元，解决“Java 不该做文档解析和向量计算”的边界问题。

核心决策：**控制面统一走 Java，数据面持短期凭证受控直连**。详见 [ADR-09](./09-ADR-平台连接方式评估.md)。

## 5. 我建议增加的 10 项扩展（可按优先级裁剪）

1. **索引任务中心**：所有解析/索引/图谱任务统一 Job 模型，支持重试、断点、DLQ、进度条。
2. **文档版本与回滚**：每次同步生成版本，可对比、可回滚，发布采用“先写新版本再删旧版本”。
3. **切片质量检查**：低质量切片自动标记（过短、纯表格、跨标题、OCR 置信度低），支持人工合并/重切。
4. **检索调试器**：一次请求展示改写、召回、融合、Rerank、ACL 过滤、最终上下文的全链路 Trace。
5. **评测与回归门禁**：Langfuse 数据集 + 离线评测 + 合并前基线对比，指标回退超阈值阻断发布。
6. **知识缺口挖掘**：聚类“无法回答/低分反馈”的问题，反向生成待补文档清单。
7. **LLM Wiki 知识沉淀**：高价值问答经人工审核后沉淀为 Wiki 页面并重新索引，降低重复推理成本。
8. **成本与配额治理**：租户/用户级 Token、存储、索引任务配额，LiteLLM 预算 + 平台侧限流双保险。
9. **安全护栏**：Prompt 注入检测、文档投毒隔离、PII 脱敏、上传病毒扫描、SSRF 防护。
10. **开放能力**：OpenAPI + API Key + Webhook，后续可接企业微信、钉钉、业务系统。

## 6. 明确不做（首期）

- 不做公网 SaaS 计费、发票、复杂运营后台。
- 不做自研向量数据库/模型训练平台。
- 不做全量文档的自动知识图谱（成本不可控），只做“精选文档图谱”。
- 不做移动端原生 App（响应式 Web 即可）。
