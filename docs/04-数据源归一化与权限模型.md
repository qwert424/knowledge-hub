# 04 数据源归一化与权限模型

## 1. 为什么需要“归一化标准”

参考项目里 RAG 只覆盖飞书，链路上每个环节都带着飞书语义（`space_id`、`node_token`、`block_type` 飞书枚举）。一旦加入本地上传、企微、S3、网页，如果继续沿用，会出现：

- 切片器要为每个来源写一套；
- 权限字段不一致，检索层无法统一过滤；
- 前端预览无法统一渲染；
- 换来源就要改索引、检索、展示三层。

因此定义 **CIR（Canonical Intermediate Representation，标准文档中间表示）**：所有来源先归一化到 CIR，再进入统一的构树、切片、增强、索引流程。**来源只影响“取数与归一化”，不影响后面任何环节。**

```text
Source Adapter → RawDocument → CIR(blocks) → StructureBuilder(BlockNode Tree)
      → Chunker → Enricher → Embedder → IndexWriter → Publisher
```

## 2. CIR 规范

```json
{
  "schemaVersion": "1.0",
  "document": {
    "sourceType": "upload|feishu|wecom|s3|web|api",
    "sourceId": "外部唯一 ID",
    "sourceUrl": "可点击链接",
    "title": "文档标题",
    "owner": {"externalId": "...", "name": "..."},
    "revision": "外部版本号/更新时间",
    "contentHash": "sha256",
    "mimeType": "application/pdf",
    "language": "zh",
    "metadata": {"spaceId": "...", "spaceTitle": "..."},
    "acl": {
      "visibility": "private|dept|tenant|public",
      "principals": ["user:u1", "role:staff", "group:g1", "dept:d1"],
      "sourceAclHash": "外部 ACL 指纹"
    }
  },
  "blocks": [
    {
      "id": "稳定块 ID（来源块 ID 或内容哈希+序号）",
      "parentId": null,
      "order": 0,
      "type": "heading|paragraph|list|table|image|code|quote|divider|attachment",
      "level": 1,
      "text": "纯文本（用于检索）",
      "markdown": "可选，保留格式",
      "html": "可选",
      "table": {"headers": [], "rows": [], "mergedCells": []},
      "image": {"objectKey": "...", "mimeType": "...", "ocrText": "...", "caption": "..."},
      "code": {"language": "python", "content": "..."},
      "references": [{"type": "doc", "id": "...", "title": "..."}],
      "sourceLocator": {"page": 3, "blockId": "..."},
      "hash": "块内容哈希"
    }
  ]
}
```

**稳定性要求**：`block.id` 在同一来源的多次同步中尽量稳定（优先用来源块 ID；没有则用 `parentId + type + 内容哈希`），用于增量 diff。

## 3. 来源适配器矩阵

| 来源 | 取数方式 | 增量识别 | ACL 来源 | 优先级 |
| --- | --- | --- | --- | --- |
| 本地上传 | 预签名直传 MinIO | 文件 hash | 上传时指定 | P0 |
| 飞书知识库 Wiki | `wiki/v2/spaces` + `docx/v1/documents` | `revision_id` + hash | Wiki 空间成员 + 文档协作者 | P0 |
| 飞书云文档 | `drive/v1/files` + `docx`/`sheets`/`bitable` | `revision` + hash | 文档协作者 | P0 |
| 企业微信文档 | 企微文档 API（wedoc） | `version` + hash | 文档成员 | P1 |
| S3/MinIO 桶 | ListObjectsV2 + 事件通知 | ETag/LastModified | Bucket 映射策略 | P1 |
| Web 站点 | sitemap/链接抓取 + trafilatura | ETag/Last-Modified + hash | 统一按 KB 授权 | P1 |
| Confluence/Notion | 官方 API | version | 空间/页面权限 | P2 |
| 数据库/API | 自定义连接器 | 游标/更新时间 | 统一按 KB 授权 | P2 |

### 3.1 适配器接口

```python
class SourceAdapter(Protocol):
    async def test(self, config: dict) -> HealthResult: ...
    async def list(self, cursor: str | None) -> AsyncIterator[SourceItem]: ...
    async def fetch(self, item: SourceItem) -> RawDocument: ...
    async def normalize(self, raw: RawDocument) -> CIR: ...
    async def current_revision(self, item: SourceItem) -> str: ...
    def map_acl(self, raw: RawDocument) -> AclSpec: ...
```

新增来源只需实现该协议 + 注册，不改索引/检索代码。

### 3.2 同步策略

- **定时**：每个数据源配置 `sync_interval`（默认 15 分钟），低峰期全量校验。
- **事件**：飞书支持的事件（文件变更/删除）走 Webhook；不支持则轮询。
- **手动**：后台“立即同步”。
- **游标**：`datasource.cursor` 保存分页/时间戳；失败不推进游标。
- **删除**：来源侧删除 → 文档标记 `offline` → 延迟 7 天清理向量（可配置）。
- **冲突**：同一文档被多个来源覆盖时，以 `source_priority` 高者为准，界面提示。

## 4. 解析器矩阵

| 格式 | 首选 | 降级 | 说明 |
| --- | --- | --- | --- |
| PDF（文本层） | PyMuPDF | pdfplumber | 快，保留坐标 |
| PDF（扫描/复杂版式） | MinerU | PaddleOCR + 版面分析 | 表格/公式/多栏 |
| DOCX | python-docx | mammoth→HTML | 保留标题/表格/图片 |
| PPTX | python-pptx | — | 一页一节 |
| XLSX | openpyxl | pandas | 每个 Sheet 一节，表头重复 |
| Markdown | markdown-it-py | — | 保留代码块/表格 |
| HTML | trafilatura | BeautifulSoup | 去导航/广告 |
| 图片 | PaddleOCR + VL 描述 | — | OCR 文本 + 语义描述 |
| 音频/视频 | Whisper（P2） | — | 转写后走文本流程 |

`ParserRouter` 依据 `mime + size + 是否扫描件 + 质量探测` 选择；解析失败自动降级并记录 `parser_used`。

### 4.1 表格处理

- 小表（≤ 50 行）：整表一个块，同时生成 Markdown 表示。
- 大表：按行切分，每片重复表头；保留 `table_row_index`。
- 合并单元格：展开为矩形，保留 `mergedCells` 元数据。
- 表格摘要：LLM 生成一句话描述，写入 `image/table caption`，提升召回。

### 4.2 图片处理

- 原图存 MinIO，记录 `objectKey`。
- OCR 文本 + VL 模型生成描述，二者都进入切片文本。
- 引用时返回预签名 URL（默认 1 小时）。
- 图片理解可按知识库开关，避免成本失控。

## 5. 构树与切片

### 5.1 BlockNode 树

- 依据标题层级（H1–H6）构建父子关系；无标题文档按段落聚类生成虚拟标题。
- 每个节点保留 `titlePath`（如 `["产品手册","安装","Linux"]`），切片继承。
- 跨标题不合并，保证语义完整。

### 5.2 切片模板

| 模板 | chunk_size | overlap | 特点 |
| --- | --- | --- | --- |
| general | 1000 | 200 | 默认，段落优先 |
| faq | 500 | 50 | 一问一答一切片 |
| legal | 1200 | 150 | 条款完整，不跨条 |
| technical | 800 | 100 | 代码整块，命令不拆 |
| table-heavy | 600 | 0 | 按行 + 表头 |

规则：

- 优先在段落/列表/表格边界切；超长段落按句子切；代码块不切。
- 父子块：父块用于上下文扩展，子块用于召回。
- 每片记录 `chunk_index`、`parent_chunk_id`、`prev/next`、`token_count`、`hash`。
- 切片前做清洗：去页眉页脚、去重复空行、统一全半角、保留原始标点。

### 5.3 质量评分（E3）

自动标记（不阻断）：

| 标记 | 规则 | 处理建议 |
| --- | --- | --- |
| `TOO_SHORT` | < 50 字 | 合并相邻 |
| `TOO_LONG` | > 2000 字 | 重切 |
| `PURE_TABLE` | 表格占比 > 90% | 表格专用模板 |
| `CROSS_HEADING` | 跨两个以上标题 | 拆分 |
| `LOW_OCR` | OCR 平均置信度 < 0.6 | 人工复核 |
| `GARBLED` | 乱码率 > 5% | 重新解析 |
| `DUPLICATE` | 与已有切片相似度 > 0.95 | 去重 |

后台按标记筛选、批量处理。

## 6. 版本与增量索引

### 6.1 版本模型

- 每次同步产生 `document_version`，`content_hash` 相同则跳过。
- `staging`：写入新切片但不参与检索。
- `active`：当前检索版本。
- `superseded`：被替代，保留 N 天用于回滚。
- `failed`：解析/写入失败，保留错误现场。

### 6.2 发布流程（最终一致 ≤ 5s）

```text
1. 写入新版本切片 status=staging
2. 回调 Java：version=staging, chunk_count
3. Java 校验（数量、质量阈值）
4. RAG Engine：删除旧版本切片 → 新版本切片 upsert 为 active
5. Java：document.active_version_id = 新版本
6. 旧版本标记 superseded
```

- 失败任一步：新版本标记 failed，旧版本继续服务。
- 回滚：把旧版本切片重新置 active，更新指针。
- 大批量（> 5000 切片）：分批 upsert，进度可查。

### 6.3 增量优化（P1）

- 块级 diff：仅对变化块重新切片/Embedding。
- 但**发布仍以版本为单位**，避免半更新状态。
- Embedding 缓存：`hash(text) → vector`，跨文档复用，降低成本 20–40%。

## 7. 权限模型

### 7.1 模型选择：RBAC + 资源 ACL + 数据范围

- **RBAC**：用户 → 角色 → 权限点（`kb:read`、`doc:write`、`index:retry`…）。
- **资源 ACL**：知识库/文档/数据源/Agent 上绑定主体（用户/角色/群组/部门）。
- **数据范围**：角色可限定 全部/本部门/本部门及下级/仅本人/自定义。
- **ABAC 补充**：文档标签 + 用户属性（如 `clearance>=internal`）用于敏感分级（P1）。

### 7.2 主体命名

统一字符串，写入 Milvus：

```text
user:{uuid}
role:{code}
group:{uuid}
dept:{uuid}
tenant:all          # 租户内公开
```

### 7.3 有效权限计算

文档最终可读主体 = 

```text
若 document.acl_mode = inherit:
    KB 的授权主体 ∪ 文档显式授权主体
若 document.acl_mode = restricted:
    文档显式授权主体（KB 管理员仍可见）
再与 visibility 合并：
    public  → tenant:all（所有人可读）
    tenant  → tenant:all（租户内）
    dept    → 对应部门主体
    private → 仅显式主体
```

- **拒绝优先**：显式 `deny` 列表在检索后二次过滤（少量，存 Postgres）。
- **外部访客**：只能命中 `visibility=public`。

### 7.4 权限传播到向量库

索引完成时计算 `acl_principals` 写入 Milvus；权限变更时：

1. Java 重算受影响文档主体集合；
2. 失效 Redis ACL 缓存；
3. 投递 `acl.sync` 任务；
4. Worker 通过 `upsert` 更新该文档所有切片的 `acl_principals`；
5. **不重新 Embedding**。

> 这是“内容与权限解耦”的关键。若 Milvus 版本不支持高效 upsert，可改为：检索时先按 `tenant/kb/status` 召回 `topK×4`，再用 Java ACL 缓存后过滤；两种模式由配置 `acl_mode: prefilter|postfilter|hybrid` 控制。

### 7.5 检索时的强制过滤

```python
# rag/engine/security.py —— 唯一允许构造 filter 的地方
def build_filter(ticket: Ticket, kb_ids: list[str], extra: dict) -> str:
    principals = ticket.principals  # 来自签名票据，绝不来自模型
    clauses = [
        f'tenant_id == "{ticket.tenant_id}"',
        f'kb_id in {to_milvus_list(kb_ids)}',
        'status == "active"',
        f'(visibility == "public" or ARRAY_CONTAINS_ANY(acl_principals, {to_milvus_list(principals)}))',
    ]
    ...
```

- 模型只能提供 `query` 和 `doc_ids/tags` 等**收窄**条件，不能扩大范围。
- 工具入参做白名单校验，禁止拼接原始表达式。
- 返回结果再做一次 `deny` 过滤与租户断言（纵深防御）。

### 7.6 票据（RetrievalTicket）

```json
{
  "iss": "knowledge-hub-backend",
  "sub": "u_123",
  "aud": "rag-engine",
  "tenant_id": "t_001",
  "principals": ["user:u_123", "role:staff", "dept:d_1", "group:g_9"],
  "kb_ids": ["kb_001"],
  "profile_id": "p_001",
  "scope": ["retrieve"],
  "exp": 1760000000,
  "jti": "..."
}
```

- RS256 签名，Java 私钥，RAG Engine 公钥。
- TTL 5 分钟；一次会话可复用，过期由 Agent 重新申请。
- 票据中包含 `kb_ids`，防止 Agent 越权指定知识库。

### 7.7 飞书 OAuth2 与身份绑定

```text
用户在 Portal 点击“飞书登录”
→ 跳转 open.feishu.cn/open-apis/authen/v1/authorize?app_id=...&redirect_uri=...&state=...
→ 回调 /api/v1/auth/feishu/callback?code=...
→ Java 用 code 换 user_access_token
→ 获取 user_info(open_id, union_id, name, avatar)
→ 按 union_id 查找/创建本地用户
→ 签发平台 JWT
```

- 飞书**机器人事件**里的 `open_id` 与应用相关；**OAuth** 也返回 `open_id`。跨应用/多租户需用 `union_id` 做稳定映射。
- 绑定表：`user_identity(user_id, provider, external_id, union_id, tenant_key, raw)`。
- 未绑定用户：`guest` 角色，仅 public。
- 离职同步：飞书通讯录事件/定时同步置禁用。

## 8. 边界与异常

| 场景 | 处理 |
| --- | --- |
| 文档超大（> 200MB） | 拒绝或走外部解析服务；提示拆分 |
| 加密 PDF | 标记 `PASSWORD_PROTECTED`，需人工提供密码 |
| 纯图片 PDF | 强制 OCR，记录置信度 |
| 表格跨页 | 按表头+续页合并，失败则拆表 |
| 同名文档 | 以 `source_id` 区分，标题加序号 |
| 来源权限为空 | 默认仅上传者 + KB 管理员，禁止公开 |
| 权限主体被删除 | 定时清理孤儿主体，检索视为不可见 |
| 数据源断连 | 保留现有索引，任务告警，不自动删除 |
| 多来源同文档 | 按优先级合并，界面标注冲突 |
| 时区/编码 | 统一 UTF-8、UTC 存储，前端本地化 |
