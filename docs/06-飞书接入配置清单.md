# 06 飞书接入配置清单

> 目标：飞书机器人可私聊/群里 @ 提问，流式更新卡片；管理员在 Portal 用飞书 OAuth2 登录；系统可按权限读取飞书知识库/云文档。  
> 参考实现：`deal_pilot/feishu/api`（lark-oapi）+ `deal_pilot/feishu/event`（长连接监听）。

## 1. 创建应用

1. 打开 [飞书开放平台](https://open.feishu.cn/app) → 创建企业自建应用。
2. 填写名称、描述、图标；记录 `App ID`、`App Secret`。
3. 「添加应用能力」→ 启用 **机器人**。
4. 「安全设置」：
   - 获取 `Encrypt Key`、`Verification Token`（用于 Webhook 验签；长连接也需要配置）。
   - 配置重定向 URL：`https://<portal-domain>/api/v1/auth/feishu/callback`（本地开发可加 `http://localhost:3000/api/v1/auth/feishu/callback`）。
   - 如使用 Webhook 模式，配置 IP 白名单（可选）。
5. 「事件与回调」：
   - 订阅方式选择 **使用长连接接收事件**（无需公网 IP，推荐）。
   - 若使用 Webhook，则填写请求地址 `https://<backend-domain>/api/v1/webhooks/feishu/event`。
6. 「版本管理与发布」→ 创建版本 → 申请发布 → 企业管理员审核 → 设置可用范围（部门/全员）。

## 2. 权限 Scope 清单

> 以“最小可用”为原则；只读优先。发布前在「权限管理」中批量开通。

### 2.1 机器人消息（必需）

| Scope | 用途 |
| --- | --- |
| `im:message` | 获取与发送单聊、群组消息 |
| `im:message:send_as_bot` | 以应用身份发消息 |
| `im:message.p2p_msg:readonly` | 读取用户发给机器人的单聊消息 |
| `im:message.group_at_msg:readonly` | 读取群里 @ 机器人的消息 |
| `im:chat:readonly` | 获取群组信息 |
| `im:resource` | 下载消息中的图片/文件 |
| `im:message.reaction:readonly` | 读取表情回复（可选，用于反馈） |

### 2.2 云文档/知识库（RAG 数据源）

| Scope | 用途 |
| --- | --- |
| `docx:document:readonly` | 读取新版文档 |
| `wiki:wiki:readonly` | 读取知识库空间与节点 |
| `drive:drive:readonly` | 读取云空间文件列表/元数据 |
| `sheets:spreadsheet:readonly` | 读取电子表格（可选） |
| `bitable:app:readonly` | 读取多维表格（可选） |
| `docs:document:readonly` | 读取旧版文档（兼容，可选） |

### 2.3 通讯录（登录与权限映射）

| Scope | 用途 |
| --- | --- |
| `contact:user.base:readonly` | 获取用户基础信息（OAuth2 必需） |
| `contact:user.employee_id:readonly` | 获取工号（可选） |
| `contact:department.base:readonly` | 读取部门信息（可选，用于组织同步） |
| `contact:user.department:readonly` | 读取用户部门关系（可选） |

### 2.4 事件

| 事件 | 用途 |
| --- | --- |
| `im.message.receive_v1` | 接收消息 |
| `im.chat.member.bot.added_v1` | 机器人被拉群，发送欢迎/说明 |
| `im.chat.member.bot.deleted_v1` | 机器人被移出群 |
| `card.action.trigger` | 卡片按钮/下拉回调 |
| `drive.file.edit_v1` | 云文档变更（若租户版本支持，用于实时增量；否则用轮询） |
| `contact.user.updated_v1` | 用户信息变更（可选） |

> 事件名称与可用性随飞书版本变化，以开放平台「事件与回调」实际列表为准。

## 3. 知识库权限（最容易踩坑）

飞书知识库（Wiki）的权限独立于应用权限：

1. 打开目标知识库 → 「···」→「权限设置」→「添加成员」。
2. 把 **应用/机器人** 添加为成员（部分租户只能添加“用户”，此时用知识库管理员账号授权，并让应用以 `tenant_access_token` 访问）。
3. 确认空间的「可阅读范围」包含该应用。
4. 子节点若单独设置了权限，需要一并授权。
5. 验证：用应用凭证调用 `GET /open-apis/wiki/v2/spaces/{space_id}/nodes`，应返回节点；否则是 403 权限问题。

## 4. OAuth2 登录流程

```text
1. 浏览器跳转：
   https://accounts.feishu.cn/open-apis/authen/v1/authorize
     ?client_id=<APP_ID>
     &redirect_uri=<URL_ENCODED_CALLBACK>
     &state=<随机数，存 Cookie>
     &scope=contact:user.base:readonly

2. 用户授权后回调：
   GET /api/v1/auth/feishu/callback?code=...&state=...

3. Java 校验 state → 换取 token：
   POST https://open.feishu.cn/open-apis/authen/v2/oauth/token
   {
     "grant_type": "authorization_code",
     "client_id": "<APP_ID>",
     "client_secret": "<APP_SECRET>",
     "code": "<CODE>",
     "redirect_uri": "<CALLBACK>"
   }
   → access_token / refresh_token / expires_in

4. 获取用户信息：
   GET https://open.feishu.cn/open-apis/authen/v1/user_info
   Authorization: Bearer <user_access_token>
   → open_id / union_id / name / avatar_url / tenant_key

5. 按 union_id 查找或创建本地用户，签发平台 JWT。
```

要点：

- **open_id 是“应用 + 用户”维度**，换应用会变；跨应用/多租户用 `union_id` 或 `user_id`。
- `state` 必须校验，防 CSRF。
- `refresh_token` 加密存储，用于离线访问（如需要）。
- 登录只获取基础信息，不请求文档权限，遵循最小授权。

## 5. 机器人消息与卡片流式

### 5.1 接收消息

- 长连接：`lark-oapi` 的 `ws.Client`，订阅 `im.message.receive_v1`。
- 事件体关键字段：`sender.sender_id.open_id`、`message.chat_id`、`message.message_type`、`message.content`、`message.mention`。
- 只处理 `text` / `post` / `image`；忽略机器人自己发的消息。
- 群聊仅在 `@机器人` 时响应（检查 mention）。
- 去重：`event_id` + `message_id`（Redis SETNX 10 分钟）。

### 5.2 发送/更新卡片

```text
1. 创建卡片消息：
   POST /open-apis/im/v1/messages?receive_id_type=chat_id
   {
     "receive_id": "oc_xxx",
     "msg_type": "interactive",
     "content": "<card json string>"
   }
   → 返回 message_id

2. 流式更新（整卡覆盖，简单可靠）：
   PATCH /open-apis/im/v1/messages/{message_id}
   { "content": "<更新后的 card json string>" }

3. 局部更新（CardKit，低带宽，进阶）：
   PUT /open-apis/cardkit/v1/cards/{card_id}/elements/{element_id}/content
```

- 节流：**每 200–500ms 合并一次**；单条消息 PATCH 频率有限（约 5 QPS），超限会 429。
- 卡片结构建议：
  - 头部：问题摘要 + 状态（思考中/检索中/生成中/完成/失败）。
  - 主体：Markdown 流式正文（`markdown` 组件）。
  - 引用区：折叠面板，列出 `[1] 文档标题` + 链接。
  - 底部：`👍 / 👎 / 继续追问 / 打开 Web` 按钮。
- 结束：补发最终快照，移除“生成中”状态；失败展示错误码与重试按钮。
- 卡片 JSON 2.0 使用 `schema: "2.0"`；注意字段大小限制（单卡片建议 < 30KB）。

### 5.3 卡片回调

- 事件 `card.action.trigger`。
- 回调需在 3 秒内响应，耗时逻辑异步处理。
- 支持动作：点赞/点踩（写反馈）、展开引用（返回详情卡）、继续追问（进入新 run）、重试。
- 回调验签：校验 `X-Lark-Signature` / 解密 `encrypt`。

## 7. 联调 Checklist

- [ ] 应用已发布，可用范围包含测试用户。
- [ ] 机器人能力已启用，能收到私聊消息。
- [ ] 群聊 @ 能收到 `im.message.receive_v1`。
- [ ] 能发送文本消息。
- [ ] 能创建卡片并 PATCH 更新，无 429。
- [ ] 卡片按钮回调能收到 `card.action.trigger`。
- [ ] OAuth2 登录成功，能拿到 `union_id`。
- [ ] 未绑定用户走访客逻辑，只看到 public 知识库。
- [ ] Wiki 空间已把应用加为成员，能列出节点。
- [ ] 能读取 Docx 块、下载图片。
- [ ] 文档变更事件（或轮询）能触发增量索引。
- [ ] 长连接断线自动重连；进程重启后能恢复。
- [ ] 消息去重生效（重复投递不重复回答）。
- [ ] 卡片内容不超限；长答案截断/分页策略明确。

## 8. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 收不到消息 | 未订阅事件 / 未发布 / 不在可用范围 | 检查事件订阅与版本发布 |
| 群聊无响应 | 未 @ 机器人 / 未开群权限 | 检查 mention 与 scope |
| 读 Wiki 403 | 应用不是空间成员 | 把应用加入知识库成员 |
| 图片下载失败 | 缺 `im:resource` | 补权限并重新发布 |
| 卡片更新 429 | 更新过于频繁 | 节流 200–500ms，合并更新 |
| OAuth 回调失败 | redirect_uri 不一致 / state 过期 | 严格比对配置 |
| open_id 对不上 | 不同应用 open_id 不同 | 用 union_id 映射 |
| 长连接频繁断 | 网络/心跳 | SDK 自动重连；加健康检查 |

## 9. 安全建议

- App Secret / Encrypt Key 只放后端环境变量或密钥管理，不进前端、不进日志。
- 事件体验签 + 解密；拒绝未签名请求。
- 卡片回调校验操作人身份，防伪造。
- 机器人只回答有权限的内容；群聊中默认不带出敏感文档，需 @ 且用户有权限。
- 日志脱敏：不记录完整消息内容与用户标识（可配置）。
- 限流：单用户 10 次/分钟，单群 30 次/分钟，防刷。
