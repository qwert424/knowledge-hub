# 07 工程结构与启动方案

## 1. 仓库与模块

```text
knowledge-hub/
├── backend/                  # Java 21 + Spring Boot 3.5，Maven 多模块
├── agent/                    # Python 3.13 + uv
├── web/
│   ├── apps/portal/          # 用户端 Next.js
│   ├── apps/admin/           # 管理端 Next.js
│   └── packages/{ui,api-client,config}/
├── deploy/
│   ├── compose/docker-compose.infra.yml
│   ├── compose/docker-compose.apps.yml
│   ├── nginx/
│   └── helm/                 # 二期
├── docs/
├── scripts/
└── Makefile
```

### 1.1 Java 模块依赖方向

```text
platform-boot
  ├── platform-iam
  ├── platform-kb
  ├── platform-datasource
  ├── platform-index
  ├── platform-retrieval
  ├── platform-chat
  ├── platform-eval
  ├── platform-graph
  ├── platform-ops
  └── platform-integration
        ↑ 所有模块可依赖 platform-common；integration 不被业务反向依赖
```

规则：

- 模块间只通过 `api` 包（接口 + DTO）依赖，禁止直接引用 `impl`。
- 禁止跨模块访问 Mapper；需要数据时调对方 Service。
- `platform-common` 不含业务逻辑。
- 第三方平台调用全部收敛到 `platform-integration`。

### 1.2 Python 分层

```text
knowledge_hub/
├── api/          # FastAPI 路由（engine）
├── agents/       # LangGraph Agent 工厂
├── rag/          # loader/parser/structure/splitter/embed/store
├── graphs/       # index / graph_build / eval 图
├── worker/       # arq 消费
├── feishu/       # event/api/card
├── tools/        # 工具注册表
├── security/     # 票据验签、内部鉴权
├── integration/  # Java 内部客户端、LiteLLM、Nacos、MinIO
└── config/       # pydantic-settings + Nacos
```

规则：

- `rag/` 不依赖 `agents/`；`agents/` 可依赖 `rag/`。
- 所有外部 IO 通过 `integration/`。
- 工具函数必须带 Pydantic 入参模型。
- 配置只从 `config/` 读取，禁止散落 `os.getenv`。

## 3. Compose Profiles

```yaml
# deploy/compose/docker-compose.infra.yml
services:
  postgres:   { profiles: ["infra"] }
  redis:      { profiles: ["infra"] }
  minio:      { profiles: ["infra"] }
  etcd:       { profiles: ["infra", "milvus"] }
  milvus:     { profiles: ["infra", "milvus"] }
  neo4j:      { profiles: ["infra", "graph"] }
  nacos:      { profiles: ["infra", "platform"] }
  litellm:    { profiles: ["infra", "platform"] }
  langfuse-web / langfuse-worker / clickhouse: { profiles: ["infra", "observability"] }
  opensandbox: { profiles: ["infra", "sandbox"] }
```

```bash
# 最小开发集
docker compose -f deploy/compose/docker-compose.infra.yml --profile infra up -d

# 含图谱
docker compose ... --profile infra --profile graph up -d

# 全量
docker compose ... --profile infra --profile graph --profile platform --profile observability up -d
```

要求：

- 所有服务有 `healthcheck`；`depends_on: condition: service_healthy`。
- 命名卷持久化；`make reset` 才删除。
- 每个服务资源限制（CPU/内存），避免本机卡死。
- 一键脚本 `scripts/bootstrap.sh` 初始化数据库、Bucket、Milvus Collection、Nacos 命名空间。

## 5. Makefile（统一入口）

```makefile
up:            ## 启动基础设施
	docker compose -f deploy/compose/docker-compose.infra.yml --profile infra up -d --wait

up-all:        ## 基础设施 + 应用
	docker compose -f deploy/compose/docker-compose.infra.yml --profile infra --profile graph up -d --wait
	docker compose -f deploy/compose/docker-compose.apps.yml up -d --build

down:
	docker compose -f deploy/compose/docker-compose.apps.yml down
	docker compose -f deploy/compose/docker-compose.infra.yml --profile infra --profile graph down

dev-backend:   ## Java 本地热启动
	cd backend && ./mvnw spring-boot:run -pl platform-boot -am

dev-agent:     ## LangGraph Server
	cd agent && uv run langgraph dev --port 8123

dev-engine:    ## RAG Engine
	cd agent && uv run uvicorn knowledge_hub.api.main:app --reload --port 8100

dev-worker:
	cd agent && uv run arq knowledge_hub.worker.settings.WorkerSettings

dev-web:
	pnpm --filter portal dev & pnpm --filter admin dev

migrate:
	cd backend && ./mvnw -pl platform-boot flyway:migrate

seed:
	cd backend && ./mvnw -pl platform-boot exec:java -Dexec.mainClass=...Seed

test:
	cd backend && ./mvnw test
	cd agent && uv run pytest
	pnpm -r test

lint:
	cd backend && ./mvnw spotless:check
	cd agent && uv run ruff check && uv run pyright
	pnpm -r lint

e2e:
	pnpm --filter e2e test

reset:         ## 危险：清空数据卷
	docker compose ... down -v
```

## 6. CI/CD

```yaml
# .github/workflows/ci.yml（或 GitLab CI）
jobs:
  backend:
    - ./mvnw -B verify
    - spotless:check
    - 单元测试 + Testcontainers（Postgres/Redis/Milvus 可选）
  agent:
    - uv sync --frozen
    - ruff check
    - pyright
    - pytest（mock 外部服务；集成测试用 compose）
  web:
    - pnpm install --frozen-lockfile
    - pnpm -r typecheck
    - pnpm -r lint
    - pnpm -r build
  contract:
    - 生成 openapi.json
    - 前后端契约测试（Schemathesis 可选）
  security:
    - 依赖漏洞扫描（Trivy / npm audit / pip-audit）
    - 密钥扫描（gitleaks）
```

合并门禁：

- 编译 + 单测 + 类型检查必须通过。
- 检索/评测基线不得回退（P1 起）。
- 数据库迁移必须向前兼容（先加列后用，删除分两次发布）。

## 7. 本地开发顺序

1. `make up`（Postgres/Redis/MinIO/Milvus/Nacos/LiteLLM/Langfuse）。
2. `make migrate` + `make seed`（默认租户、管理员、示例 KB）。
3. `make dev-backend`。
4. `make dev-engine` + `make dev-worker`。
5. `make dev-agent`。
6. `make dev-web`。
7. 打开 `http://localhost:3000`（Portal）、`http://localhost:3001`（Admin）。

## 8. 测试策略

| 层 | 工具 | 覆盖 |
| --- | --- | --- |
| Java 单测 | JUnit 5 + Mockito | Service、ACL 计算、策略解析 |
| Java 集成 | Testcontainers | Repository、Flyway、SSE |
| Python 单测 | pytest | 解析、切片、filter 构造、票据 |
| Python 集成 | pytest + testcontainers | Milvus 写入/检索、Neo4j |
| 契约 | OpenAPI + Schemathesis | 前后端字段一致 |
| E2E | Playwright | 登录→上传→索引→对话→引用 |
| 评测 | Langfuse + 自研 runner | 检索/生成指标回归 |
| 安全 | OWASP ZAP（可选） | 越权、注入、SSRF |

关键测试用例（必须有）：

- 租户隔离：A 用户用 B 的 doc_id 取文档/切片/引用 → 403/404。
- ACL：撤权后 60s 内检索不到；public 文档所有人可见。
- 票据：过期/篡改/换 tenant → 拒绝。
- 索引：重复消费幂等；失败可重试；旧版本不被检索。
- 切片：表格/代码/跨标题边界正确。
- SSE：断线重连、停止生成、错误事件。

## 9. 子 Agent 开发编排（后续生产时使用）

建议把工作拆成**互不重叠的文件域**，每个子 Agent 只改自己的目录，减少冲突：

| 子 Agent | 负责目录 | 交付 |
| --- | --- | --- |
| A1 基座 | `backend/platform-common|boot|iam`、`deploy` | 登录、租户、审计、Compose、Flyway |
| A2 知识与数据源 | `backend/platform-kb|datasource` | KB/文档/上传/同步 API |
| A3 索引编排 | `backend/platform-index`、`agent/worker` | Job、Outbox、回调、重试 |
| A4 RAG 解析 | `agent/rag/{loader,parser,structure,splitter}` | CIR、解析器、切片 |
| A5 检索 | `agent/rag/{embed,store,retriever}`、`engine` | 混合检索、融合、Rerank、ACL |
| A6 Agent | `agent/agents`、`tools`、`middlewares` | 主/检索/图谱 Agent |
| A7 前端用户端 | `web/apps/portal` | 对话、引用、反馈 |
| A8 前端管理端 | `web/apps/admin` | 8 大模块 |
| A9 图谱 | `agent/graphs`、`backend/platform-graph` | 抽取、社区、查询 |
| A10 飞书 | `agent/feishu`、`backend/platform-integration/feishu` | 事件、卡片、OAuth |

协作规则：

- 先冻结 `docs/03` 的接口与 DTO，再并行。
- 每个 Agent 产出自己的单测；主 Agent 负责集成与验收。
- 公共库变更由主 Agent 统一提交，子 Agent 不跨域改文件。
- 每日合并一次，避免长分支。
