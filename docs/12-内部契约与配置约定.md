## 2. 配置分层（不要再把模型名写进 .env）

| 层 | 放什么 | 位置 |
| --- | --- | --- |
| `.env` | **只放接入点、凭证、端口** | 仓库根 `.env`（gitignore） |


### 3.2 索引 `POST /v1/index/jobs`（由 Worker 消费后调用，或后台直接触发）

```json
{"jobId":"","documentId":"","versionId":"","kbId":"","objectKey":"","contentHash":"",
 "title":"","collectionName":"kh_demo_1024","embeddingDim":1024,

```

引擎必须回调 Java（见 §4），不允许自己改业务库。

### 3.3 对话 `POST /v1/chat/stream`（SSE）

请求体：

```json
{"tenant_id":"","conversation_id":"","user_message_id":"","assistant_message_id":"",
 "query":"","kb_ids":["uuid"],"ticket":"","profile":{},"history":[{"role":"user","content":""}],
 "trace_id":"","model":"chat-basic","resume":false,"resume_prefix":""}
```

- `kb_ids` 为空**不再等于"不检索"**：由 JEV router 决定（闲聊走 direct，问企业内部事实会检索全部已授权知识库）。
- `model` 必须是 LiteLLM 网关真实别名，Java 侧已做白名单校验（不在清单直接 400）。
- `resume=true` 时用 `resume_prefix`（已产出的半截回答）续写，不检索、不重复已写内容。

事件（`event:` + `data:`）：

| event | data |
| --- | --- |
| `status` | `{"stage":"route"\|"retrieve"\|"direct"\|"generate"\|"resume"}` |
| `token` | `{"delta":"..."}` |
| `citation` | `{"chunk_id":"","doc_id":"","title":"","url":"","snippet":"","score":0.8}` |
| `error` | `{"code":"","message":"","retryable":false}` |
| `done` | `{"usage":{"model":"","input_tokens":0,"output_tokens":0}}`；Java 追加一帧 `{"messageId":"","citationCount":0,"stopped":false}` |

`stopped=true` 表示"引擎没有发出 done，连接被提前关闭"，前端据此显示「继续」（`POST /api/v1/chat/sessions/{id}/messages/{messageId}/resume`）。

### 3.5 Agent（工具 / 子 Agent / 沙箱 / skills）

`POST /v1/agent/chat` 复用同一份请求体与 SSE 事件，但走 Nacos AgentSpec 描述的工具循环：

- 工具来自 `spec.tools`，不可用的名会出现在 `status.skipped_tools`，不伪造能力；
- `spec.subagents` 会额外注册 `task` 工具（把检索类子任务委派给子 Agent）；
- `spec.skills` 非空时，skill zip 会下载并解压到沙箱 `/shared/skills/<agent>/<name>`，
  `SKILL.md` 摘要进系统提示词，模型可用 `load_skill(name, path)` 读取；
- `deploy` 工具把沙箱产物上传到 MinIO `agent-artifacts`（按 tenant/user 分目录），返回预签名直链；
- `ask_user_question` 支持 `options`（最多 6 个候选），`status.stage=awaiting_user` 会带上
  `question` 与 `options`，用户端据此渲染成可点选的卡片（人机回路）；
- 中间件链（`runtime/middleware.py`）：
  | 阶段 | `status.stage` | 作用 | 失败时 |
  | --- | --- | --- | --- |
  | 规划 | `plan` | 先产出 goal/steps/needs_retrieval（严格 JSON，4s 预算），注入 `<plan>` 块 | 静默跳过，按原流程跑 |
  | 复核 | `review` | 检查答非所问/编造/泄露，`need_fix` 时按建议改写一次 | 静默跳过 |
  | 安全 | `security` | 确定性扫描：密钥样式、内部主机名、内网 IP、提示词回显；命中直接替换为安全答复 | 命中即拦截 |
  开关：Nacos `agent.plan_enabled / review_enabled / security_scan_enabled`（默认全开）。

## 5. Redis Stream

| Key | 生产者 | 消费者 | 字段 |
| --- | --- | --- | --- |
| `kh:stream:index.job.created` | Java OutboxPublisher | Python Worker | `tenantId`, `payload`(JSON), `eventId` |
| `kh:stream:acl.sync` | Java | Worker | 同上 |
| `kh:stream:graph.jobs` | Java | Worker | 同上 |

消费使用 consumer group `kh-workers`；失败 3 次进 `kh:stream:<topic>.dlq`。重复投递必须幂等（按 `eventId`）。

### 8.4 已修复的实测缺陷（供复盘）

| 缺陷 | 根因 | 修复 |
| --- | --- | --- |
| 审计/Outbox 插入报 `null value in column "id"` | `bigserial` 主键用了 `IdType.INPUT` | 改 `IdType.AUTO` |
| jsonb 列写入失败 | 自定义 typeHandler 未注册且与 MyBatis-Plus 冲突 | 去掉 handler，JDBC 加 `stringtype=unspecified` |
| `No typehandler found for property id` (UUID) | MyBatis 无内置 UUID handler | 注册 `UuidTypeHandler` |
| 内部回调 403 `TENANT_MISSING` | Worker 无 JWT | 由 job 行反查租户并在线程内绑定 |
| SSE 首帧后 401 | 异步二次派发未认证 | 放行 `ASYNC/ERROR` dispatcher + `shouldNotFilterAsyncDispatch=false` |
| 前端 500（评测模块） | `platform-eval` 的 mapper/service/controller 未落盘 | 补全并验证 |
| LiteLLM 401 / 模型空 | `.env` 缺 `LITELLM_API_KEY` | 用 `LITELLM_MASTER_KEY` 覆盖（模型 7 个可见） |
| MinIO 403 | 复用栈的 `MINIO_ACCESS_KEY` 只对 `deal-pilot` 桶有权限 | 新建 `kh-app` 用户 + `kh-rw` 策略（仅 `knowledge-hub` 桶） |

### 8.5 当前启动方式（本地 Docker）

```powershell
# 从项目根目录统一启动（Compose 项目名 knowledge-hub）
.\scripts\up.ps1

# 需要单独重建/启动 Agent 时
docker compose --profile app -p knowledge-hub -f deploy/compose/docker-compose.yml --env-file .env up -d --build --wait kh-agent
```

正式 RAG 引擎由 Compose 服务 `kh-agent` 管理，监听宿主机 `8100`；索引 Worker 是独立服务 `kh-worker`。旧验收容器 `kh-agent-verify`（镜像标签 `verify`、宿主机端口 `18100`）不是正式服务，已由 Compose 管理的 `kh-agent` 替代。数据库与 Redis 也统一由该 Compose 项目管理，不再使用手工 `docker run` 创建 `kh-verify-*` 容器。
